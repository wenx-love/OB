# Phase 4 位置级替换验收指南

## 目标

验证 OB-Recover 的位置级 AST 替换功能，证明系统能够：

1. 根据 `scriptId + scriptHash + start/end` 定位具体的 AST 节点
2. 不进行全局文本替换
3. 相同调用文本出现在多个位置时，只替换被捕获并验证的位置
4. 同一位置出现冲突证据时拒绝替换

## 测试文件

- `test-pages/phase4-position-level.html`
- `test-pages/phase4-position-level.js`

## 测试场景

### 场景 1：相同文本不同位置

源码中有 3 个相同的调用文本 `_0x123456(0x10)`：

- **位置 A**（第 30 行）：被捕获并验证 → **应替换为 `"Signature"`**
- **位置 B**（第 35 行）：未被捕获 → **必须保留原样**
- **位置 C**（第 38 行）：被捕获并验证 → **应替换为 `"Signature"`**

### 场景 2：冲突证据拒绝

- **位置 D**（第 47-48 行）：`_0xabcdef(0x20)` 被调用两次，返回不同值（"Conflict1" 和 "Conflict2"）→ **必须拒绝替换**

## 操作步骤

### 1. 打开测试页面

1. 在 Chrome 中安装 OB-Recover 扩展
2. 打开 DevTools
3. 导航到 `file:///D:/Projects/ob-recover/test-pages/phase4-position-level.html`
4. 切换到 **OB-Recover** 面板

### 2. 捕获位置 A 和 C

我们需要**有选择地**捕获位置 A 和 C，但**不捕获**位置 B。这里有两种方法：

#### 方法 1：使用条件断点（推荐）

1. 在 **Sources** 面板中打开 `phase4-position-level.js`
2. 在第 30 行（位置 A）设置断点
3. 在第 38 行（位置 C）设置断点
4. **不要**在第 35 行（位置 B）设置断点
5. 刷新页面，逐个触发断点
6. 每次暂停时，OB-Recover 会捕获调用和返回值
7. 继续执行直到页面加载完成

#### 方法 2：修改源码（更精确）

临时修改 `phase4-position-level.js`，在位置 B 前后添加注释：

```javascript
// 位置 A：被捕获并验证的调用
var resultA = _0x123456(0x10);

// 位置 B：使用内联值，不调用函数
var resultB = 'Signature'; // 直接使用值，跳过捕获

// 位置 C：被捕获并验证的调用
var resultC = _0x123456(0x10);
```

这样位置 B 不会生成 `_0x123456(0x10)` 的调用，验证后再恢复源码。

### 3. 验证捕获结果

在 **OB-Recover** 面板的 **捕获列表** 中，应该看到：

- `_0x123456(0x10)` → `"Signature"`（2 次捕获，来自位置 A 和 C）
- `_0xabcdef(0x20)` → `"Conflict1"`（1 次）
- `_0xabcdef(0x20)` → `"Conflict2"`（1 次）

### 4. 执行 Dry Run

1. 点击 **「验证捕获结果」** 按钮
2. 检查 **Dry Run** 结果：
   - `_0x123456(0x10)` 的 2 个候选应该都通过验证（状态：✅）
   - `_0xabcdef(0x20)` 的 2 个候选应该被拒绝（原因：`CONFLICTING_EVIDENCE`）

### 5. 应用替换

1. 选择 `phase4-position-level.js` 脚本
2. 点击 **「应用已验证替换」** 按钮
3. 查看 **替换报告**：
   - 替换数量：2（位置 A 和 C）
   - 拒绝数量：2（位置 D 的两次调用）

### 6. 验证最终代码

在 **还原代码** 区域，检查替换结果：

```javascript
// 位置 A：被捕获并验证的调用
// 预期：应该被替换为 "Signature"
var resultA = "Signature";

// 位置 B：相同文本，但未被捕获的调用
// 预期：必须保留原样 _0x123456(0x10)
var resultB = _0x123456(0x10);

// 位置 C：被捕获并验证的调用
// 预期：应该被替换为 "Signature"
var resultC = "Signature";

// 位置 D：有冲突证据的调用
// 预期：因为返回值不一致，应该被拒绝替换
var resultD1 = _0xabcdef(0x20);
var resultD2 = _0xabcdef(0x20);
```

## 验收标准

✅ **通过条件**：

1. 位置 A 被替换为 `"Signature"`
2. 位置 B **保留原样** `_0x123456(0x10)`（这是关键！）
3. 位置 C 被替换为 `"Signature"`
4. 位置 D 的两次调用都**保留原样** `_0xabcdef(0x20)`
5. 替换报告显示：
   - 替换数量：2
   - 拒绝数量：2
   - 拒绝原因包含 `CONFLICTING_EVIDENCE`

❌ **失败条件**：

1. 位置 B 被替换（说明系统使用了全局文本替换，而非位置级 AST 替换）
2. 位置 D 被替换（说明冲突检测失败）
3. 位置 A 或 C 未被替换（说明正常的验证替换失败）

## 故障排查

### 问题 1：位置 B 也被替换了

**原因**：系统使用了全局文本替换，而非位置级 AST 替换。

**检查**：
- 查看 `applyVerifiedReplacements` 函数是否使用了 `ast-replace.ts`
- 确认替换逻辑使用了 `scriptId + scriptHash + start/end` 定位
- 检查是否有代码回退到了文本级替换

### 问题 2：位置 A 或 C 未被替换

**原因**：捕获或验证失败。

**检查**：
- 确认捕获列表中有 `_0x123456(0x10)` 的记录
- 确认 Dry Run 结果显示这些候选通过验证
- 检查是否有其他拒绝原因（如 `scriptId` 不匹配、hash 不匹配等）

### 问题 3：位置 D 被替换了

**原因**：冲突检测失败。

**检查**：
- 确认捕获列表中有 `_0xabcdef(0x20)` 的两条记录，返回值不同
- 确认 Dry Run 结果显示冲突原因
- 检查 `groupCapturesByCallSignature` 是否正确分组
- 检查 `validateGroup` 是否正确检测冲突

## 注意事项

1. **不要使用「全部替换」功能**，因为那是 Phase 2 的文本级替换
2. **必须使用「应用已验证替换」按钮**，这是 Phase 4 的位置级替换
3. **刷新页面后需要重新捕获**，因为 `scriptId` 会变化
4. **确保扩展已启用捕获功能**（面板右上角的开关）
