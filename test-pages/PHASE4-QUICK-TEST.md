# Phase 4 快速验收指南

## 文件位置

- 测试页面：`D:\Projects\ob-recover\test-pages\phase4-position-level-auto.html`
- 扩展构建：`D:\Projects\ob-recover\dist\`

## 快速验收步骤（5 分钟）

### 1. 加载扩展 (30 秒)

1. 在 Chrome 地址栏输入：`chrome://extensions/`
2. 开启「开发者模式」（右上角）
3. 点击「加载已解压的扩展程序」
4. 选择 `D:\Projects\ob-recover\dist` 目录

### 2. 打开测试页面 (10 秒)

在 Chrome 中打开：`file:///D:/Projects/ob-recover/test-pages/phase4-position-level-auto.html`

### 3. 打开 DevTools (10 秒)

1. 按 `F12` 或右键 → 检查
2. 切换到 **OB-Recover** 标签
3. 确保右上角的捕获开关是**开启**状态

### 4. 刷新页面捕获 (10 秒)

1. 按 `F5` 或刷新按钮
2. 等待页面加载完成（标题变为 "phase4-ready"）
3. 在 **捕获列表** 中应该看到多条记录

### 5. 执行 Dry Run (30 秒)

1. 点击「验证捕获结果」按钮
2. 查看验证结果：
   - ✅ `_0x123456(0x10)` → `"Signature"`（应该有记录，可能是 2-3 个）
   - ⚠️ `_0xabcdef(0x20)` → 冲突（应该有 2 个，返回值不同）

### 6. 应用替换 (30 秒)

1. 在脚本列表中选择 `phase4-position-level-auto.js`
2. 点击「应用已验证替换」按钮
3. 等待替换完成

### 7. 验证结果 (2 分钟)

查看**还原代码**区域，关键检查以下位置：

```javascript
// 第 26 行 - 位置 A
var resultA = "Signature";        // ✅ 应该被替换 (0x10 → "Signature")

// 第 30 行 - 位置 B（关键！）
var resultB = _0x123456(0x11);   // ✅ 必须保留原样（参数不同：0x11 ≠ 0x10）

// 第 34 行 - 位置 C
var resultC = "Signature";        // ✅ 应该被替换 (0x10 → "Signature")

// 第 42-43 行 - 位置 D
var resultD1 = _0xabcdef(0x20);  // ✅ 应该拒绝替换（冲突）
var resultD2 = _0xabcdef(0x20);  // ✅ 应该拒绝替换（冲突）
```

### 8. 检查替换报告 (1 分钟)

在「应用已验证替换」按钮下方的结果区域，应该看到：

- **替换数量**：根据实际捕获情况（理想情况下是 2，即位置 A 和 C）
- **拒绝数量**：至少 2（位置 D 的两次调用）
- **拒绝原因**：应包含 `CONFLICTING_EVIDENCE`

## 验收标准

### ✅ 通过条件

1. **位置 B 保留原样**（这是最关键的！）
   - 位置 B 应该是 `_0x123456(0x11)`，而不是被替换
   - 因为只有参数 `0x10` 被验证为 `"Signature"`，参数 `0x11` 没有对应的替换规则
2. **位置 A 和 C 被替换为 `"Signature"`**
   - 这两个位置使用参数 `0x10`，匹配验证结果
3. **位置 D 被拒绝替换**（因为冲突）
4. **原始源码不变**：切换到「原始代码」标签，应该看到完整的原始 JS

### ❌ 失败情况

| 现象 | 原因 | 说明 |
|------|------|------|
| 位置 B 被替换了 | 使用了全局文本替换 | **严重问题**：位置级替换失败 |
| 位置 A 或 C 未替换 | 捕获或验证失败 | 检查捕获列表和 Dry Run 结果 |
| 位置 D 被替换了 | 冲突检测失败 | 检查冲突检测逻辑 |
| 原始源码被修改 | 替换逻辑错误 | 应该只修改 `recovered`，不修改 `source` |

## 故障排查

### 问题 1：捕获列表为空

**原因**：
- 扩展未启用捕获功能
- 页面加载过快，捕获未完成

**解决**：
1. 检查面板右上角的捕获开关是否开启
2. 打开 DevTools 后再刷新页面
3. 在 Console 中查看是否有捕获相关的日志

### 问题 2：位置 B 被捕获了

**原因**：
- 所有调用都被捕获了（这是正常的，因为没有选择性捕获）

**解决**：
- 这是预期行为，系统会捕获所有调用
- 关键是**替换时只替换验证通过的位置**
- 如果所有 3 个位置都被捕获并验证，那么都应该被替换
- **验收重点**：在有些位置未被捕获/验证的情况下，只替换那些通过验证的

### 问题 3：所有位置都被替换了

**分析**：
- 如果位置 A、B、C 都被捕获并验证，那么都被替换是**正常的**
- 这说明**捕获太完整了**，无法测试"选择性替换"

**解决方案**：
1. **修改测试脚本**，让位置 B 使用不同的参数：
   ```javascript
   var resultB = _0x123456(0x11); // 使用不同参数
   ```
   这样位置 B 的调用签名不同，不会影响位置 A 和 C 的替换

2. **或者**：创建一个位置 B 未被验证的场景（例如手动删除捕获记录）
